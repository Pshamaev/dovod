# Сторонние компоненты оболочки Довода

Этот файл дополняет `NOTICE` (краткая запись об авторстве Qwen Code и Node.js)
перечнем сторонних компонентов, из которых собрана оболочка `desktop-shell`
(установщик Довода). Он касается только самой оболочки; сторонние компоненты
пакета конвейера (`dovod-tools`, Tesseract, RapidOCR, PyMuPDF и прочие) сюда не
входят, см. раздел "Пакет конвейера" ниже.

## Прочие прямые зависимости Rust-части оболочки

Версии - из `packages/desktop-shell/src-tauri/Cargo.lock` (точные собранные
версии, не диапазоны из Cargo.toml). Лицензии в столбце ниже - по памяти и
общеизвестным сведениям об этих крейтах, **не перепроверены построчно по
фактическим файлам LICENSE внутри скачанных крейтов** - в этой сессии нет
доступа к cargo и к сети вне разрешённых каналов, чтобы прогнать `cargo
metadata` или `cargo license`. Перед релизом с подписью это нужно
подтвердить отдельно (команда для машины с cargo: `cargo metadata
--format-version=1 --manifest-path packages/desktop-shell/src-tauri/Cargo.toml
| cargo-license` или аналогичный инструмент, запущенный из
`packages/desktop-shell/src-tauri`).

**Важно и не сделано:** список выше - только прямые зависимости (те, что
названы в `Cargo.toml`). У оболочки на Tauri транзитивных зависимостей
(зависимостей зависимостей) обычно несколько сотен - в `Cargo.lock` этого
проекта их 5540 строк. Полный перечень с лицензиями каждой транзитивной
зависимости не составлен: без cargo в этой сессии его физически нельзя было
бы проверить, а переписывать вручную несколько сотен записей из памяти без
проверки означало бы написать документ с непроверенными утверждениями - то,
что в отчёте DESKTOP_016_D (раздел про PyMuPDF) было прямо названо
недопустимым. Перед релизом с подписью владельцу или следующему исполнителю
с доступом к cargo нужно сгенерировать полный перечень (например
`cargo install cargo-license`, затем `cargo license --manifest-path
packages/desktop-shell/src-tauri/Cargo.toml` или `cargo-about`) и заменить
эту заметку результатом.

## Пакет конвейера (dovod-tools)

Пакет конвейера (`dovod_prompts.exe`, RapidOCR, Tesseract, PyMuPDF и другие
зависимости распознавания и обработки документов) собирается в другом
репозитории (garant-bot) и попадает в установщик Довода как готовый архив
(см. `packages/desktop-shell/dovod-tools.json` и `scripts/prepare-runtime.js`,
функция `installDovodTools()`). Его сторонние компоненты и их лицензии
**не входят в этот файл** - они описываются в собственном
`THIRD_PARTY_NOTICES.md` того пакета и устанавливаются рядом с
`dovod_prompts.exe` внутри `runtime/qwen-code/dovod-tools/`.

Открытый вопрос из отчёта DESKTOP_016_D (раздел 2): лицензия PyMuPDF
(`pymupdf`/`fitz`) распространяется по двойной схеме AGPL v3 или коммерческая
лицензия Artifex - для закрытого коммерческого продукта это требует либо
покупки коммерческой лицензии, либо замены библиотеки. Этот вопрос до сих пор
не решён владельцем и не проверен по фактическим файлам собранного пакета
(в этой сессии нет доступа к собранному dovod-tools) - он остаётся открытым
и должен быть закрыт до релиза, которому важна юридическая чистота поставки.
