# CLAUDE.md: правила работы в репозитории Довода

Действуют для любой сессии любого агента (Claude Code, Codex и др.) в этой папке.
Это форк Qwen Code Desktop под именем «Довод» (настольная рабочая среда дела для
юристов). AGENTS.md описывает соглашения исходного проекта (сборка, стиль, тесты);
он остаётся справочником по стеку, но при расхождении с этим файлом действует этот файл.
Владелец продукта: адвокат, не инженер. Отчёты и сообщения коммитов по-русски, без тире.

## 0. Иерархия истины

1. Этот файл.
2. `PROGRESS.md` в корне: журнал сессий (дата, что сделано, чем проверено, что дальше).
   Если его нет, создать при первом же шаге.
3. `git log`.
4. AGENTS.md и docs/ исходного проекта: только техника стека, не продуктовые решения.
Продуктовые решения (что такое Довод, что нельзя, приоритеты) принимает владелец
вне репозитория; агент их не переизобретает и не отменяет.

## 1. Что здесь наше, а что наследие

Наши изменения живут в узком контуре:
- `packages/desktop-shell` (оболочка Tauri 2, идентификатор `law.dovod.desktop`, русский интерфейс);
- `packages/web-shell` (интерфейс, локаль ru по умолчанию, русские фразы ожидания);
- `site/` (лендинг dovod.law, один HTML, mark.svg, favicon.svg; Vercel собирает папку автоматически при пуше в main);
- `.github/workflows/desktop-release.yml` (сборка DOVOD-Setup-<версия>-x64.exe, dry_run без подписи).
Всё остальное это исходный проект. Его не рефакторить, не «улучшать» и не обновлять
из апстрима без прямого задания.

Конвейер дела (dovod-tools: извлечение текста, OCR, фильтр приватности, facts_check,
restore, Маска) и бот живут в ДРУГОМ репозитории (garant-bot). Здесь их нет и здесь
их не копировать. Правки конвейера делаются там по его CLAUDE.md.

## 2. Что нельзя без прямого задания владельца

- Показывать пользователю бренд исходного проекта на экранах Довода (проверяется глазами перед релизом).
- Удалять LICENSE и NOTICE, менять условия лицензии Apache 2.0; изменённые файлы исходного проекта помечать.
- Добавлять телеметрию, автообновление с чужого сервера, любую отправку данных дела наружу.
   Наружу уходят только обезличенный текст к провайдеру модели и реквизиты для проверки ссылок.
- Зашивать имя модели в код: имя модели берётся из настроек и проверяется списком моделей провайдера.
- Открывать агенту корень папки дела: рабочая папка только `для_модели`.
- Трогать 55 унаследованных workflow в `.github/workflows` кроме `desktop-release.yml`
   (они отключены целиком в настройках репозитория; перед релизом включается только desktop-release).

## 3. Прогоны только в файл

Любой прогон (сборка, тесты, typecheck, lint) выполняется с полным выводом в файл
`logs/ГГГГ-ММ-ДД_<шаг>.log`, в чат идут только код возврата, строки с ошибками
(не более 50) и последние 5 строк. Папка `logs/` не коммитится. Файлы крупнее 100 КБ
не читать целиком, только grep и диапазон строк. Причина: длинные выводы обрывают
сессию с пустым итоговым ответом.

## 4. Один шаг, одна правка, один коммит

Задание дробится на шаги. После каждого шага: коммит (по-русски, префикс feat/fix/
test/docs/chore/site), строка в `PROGRESS.md`. Незакоммиченная работа считается
несделанной. Ветка: локальная `main-dovod`, пуш в апстрим репозитория Pshamaev/dovod
командой `git push origin HEAD:main`. Пуш делает владелец, если задание прямо не
разрешило пушить. В main уходит только то, что собралось и прошло тесты с нулём падений.

## 5. Отчёт сводкой

Итог сессии: что изменено (файлы), чем проверено (прогоны и коды возврата), хеши
коммитов, что не удалось и почему, открытые вопросы. Логи и содержимое файлов только
по прямому запросу. На длинных заданиях отчёт писать по ходу в
`docs/reports/ГГГГ-ММ-ДД_<тема>.md` и в конце вставлять его целиком.

## 6. Начало сессии

Сессия начинается с чтения `PROGRESS.md` и `git log --oneline -15`, а не с расспросов
и не с изучения всего репозитория. Если задание неясно, задать один вопрос текстом.

## 7. Среда владельца

Windows, PowerShell 5.1 (цепочки через `&&` не работают; путь к exe в кавычках
запускается через `& "путь"`). Файлы не удалять, а переносить в `_to_delete/`.
Сборка установщика идёт в GitHub Actions (workflow «Desktop Release»), локально
собирается только web-shell и тесты. Релизы: 0.1.5 последний собранный, следующий
0.1.6; перед релизом включить desktop-release.yml, после релиза отключить Actions обратно.

## 8. Приёмка перед релизом (чеклист)

- Чистая Windows 11 без Python и Node: установка одним файлом, запуск, экран «Открыть дело».
- Ни одного упоминания исходного проекта на экранах пользователя.
- Ключ модели не виден в интерфейсе.
- Русский интерфейс по умолчанию независимо от языка ОС.
- Оболочка открывает агенту только `для_модели`.
